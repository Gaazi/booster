# Review of recent Booster changes

Scope: changes after `d136fde` through `a9e71bf`, with follow-up regression fixes.
This is a review of recent work, not proof that all deployments are bug-free.

## Confirmed problems and fixes

| Finding | Reproduction and fix |
| :--- | :--- |
| Cookie-specific CSS could be shared across users | Alice's response was returned for Bob. Credentials now bypass lookup/admission on every path, regardless of extension. |
| Cached bytes and security headers changed | CSS string content changed on the second request; cache hits omitted Cache-Control/security headers. Cache original bytes and replay end-to-end headers, with Age and origin-bounded lifetime. |
| HEAD could seed an empty GET response | Cold HEAD followed by GET returned an empty body. Only GET bodies populate storage. |
| Origin freshness was ignored | max-age=1 survived beyond one second under a 300-second configured TTL. Origin age/freshness now caps storage and edge headers. |
| Responses without explicit public policy were shared | A counter stopped reaching the origin despite no public declaration. Explicit public policy is required. |
| no-transform was ignored | Private/no-transform bytes were compressed. Transformation now respects request/response directives and encoded/range responses. |
| Forbidden encoding selected | br;q=0 won over gzip;q=1. Codec quality values now control selection. |
| Writes could leave stale concurrent reads | A GET during a pending write populated an old value that survived write completion. Pre/post invalidation and generation checks protect in-flight captures. |
| Explicit writeHead bypassed edge privacy protection | A private response retained public CDN headers after committing headers early. Both writeHead header forms now receive conservative edge protection. |
| Tested source differed from installed package | Tests imported TypeScript, while package exports selected separately maintained JavaScript. Build and declarations now come from TypeScript; the same native TS suite runs against the installed archive. |

Additional safeguards cover bounded resident body bytes, explicit zero budgets,
outer host privacy headers, stream passthrough without retained chunks, and JSON
minification preserving large numbers/string content and invalid UTF-8 bytes.
Legacy source `.js` files are not modified or distributed by this change.

## Verification

- The first eight new regressions failed against the reviewed baseline; the
  explicit-writeHead regression also failed before its guard was added.
- TypeScript build, generated public declaration check and all 31 native tests
  passed against source and an actually installed Node tarball locally.
- Full Python suite: 183 passed; `pip check` passed. Python engine source was
  unchanged. One existing Starlette deprecation warning remains.
- Node native test execution emits a package module-detection warning; the
  distributed runtime uses compiled CommonJS and does not need TS stripping.
- Final GitHub matrix/build verification is recorded in PROJECT_STATE.md and
  linked in the task result after pushing the fixes.

## Limits

Per-process invalidation is not multi-worker coordination. This review did not
deploy a website, promote demo/main, validate a physical phone or prove parity
for every framework. Native source tests require Node 22.18+; installation uses
compiled runtime output. Authentication and outer host/CORS policies still
belong to the consuming application.

The policy follows [HTTP caching requirements](https://www.rfc-editor.org/rfc/rfc9111.html).
Compilation also avoids Node's documented restriction on
[native TypeScript under node_modules](https://nodejs.org/api/typescript.html#type-stripping-in-dependencies).
