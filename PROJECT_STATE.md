# Project State
Updated: 2026-10-20 15:40
## Done
- Phase 1 (e82d78d) plugin recipe and conformance checklist; Phase 2 (cc48328) reference host that runs the checklist in CI; DMS host pilot (DMS commits 029f0bd1, 1981d22d on `dev` only) with 319 passing tests and a healthy live dev site.
- Consumption path (cd1a4f6): `booster init` scaffolds a ready-to-edit `booster_plugin.py` into any host project, never overwrites existing work, standard library only. The Node engine received the same path: `npx booster-node init` writes `booster_plugin.ts` and the matching `booster.json` through the new `bin` entry, so both engines are consumed with one command from GitHub.
- Shared invalidation (724e060): `booster/invalidation.py` with the bus protocol, a local no-op and a file-backed bus for workers on one host. `RocketBooster` and `SpeedProxyServer` accept `invalidation_bus`, publish their own invalidation scope and apply peer notices before serving; the admin clear now reaches every worker; `get_status()` reports `shared` or `process`. Two real worker processes prove the peer returns fresh bytes after the other worker wrote, and the process-local behaviour is unchanged without a bus.
- Declarative site configuration (72e0a53): `booster/site_config.py` reads one JSON file into a `SiteConfig`, rejects unknown keys, relative prefixes and non-positive limits, and `booster init --config` writes the matching `booster.json` that the generated adapter prefers.
- Operator visibility (cb35078): `booster/bypass.py` counts fixed reason names for every response that was not stored; `metrics["bypass_reasons"]` explains a route without recording any cookie, token, path or payload.
- Node parity: the Node engine gained the same features - `bypass.ts` reason counters, `status.ts` operator snapshot with `middleware.status()`, `invalidation.ts` file bus, `site-config.ts` JSON configuration and the route policy that was missing entirely. Node suite 47 passed (was 31), TypeScript build and strict type check pass.
- Python suite 216 passed, 1 existing Starlette deprecation warning. `CODEMAP.md` regenerated with `refresh_docs.py`.
- Documentation of record updated: `docs/FEATURES_AND_ARCHITECTURE.md` gained the shared invalidation, site configuration and bypass reason sections plus the corrected install and verification steps; `docs/USE_CASES.md` describes the shared bus; `docs/NEXT_STEPS.md` now hands off the real remaining work. All relative documentation links resolve.
- Proof path for every supported stack: the conformance checklist now carries a Django (WSGI) variant and a Node.js variant next to the ASGI one, and `examples/django_host.py` shows the Django wiring with a regression test (218 Python tests).
- Published artifact proof: the CI smoke steps now run the installed command from the built wheel and the installed tarball and check that both files appear in a scratch host project. Both flows were executed locally before the change (Python 226 tests, Node 48 tests).
- Measurement tooling: `booster measure <url>` reports the status, size, cache headers, p50/p95 timings and whether the engine could store the response, using the engine's own privacy rules. Standard library only.
- Opt-in Vary allow list: `allowed_vary=("user-agent",)` (Python) and `allowedVary` (Node) admit one hosting-layer Vary field for sites that prove the bytes are identical for every user agent. The default stays closed. Found by measuring the live DMS dev site, where the LiteSpeed layer adds `Vary: User-Agent` and the engine therefore stored nothing.
- Version bumped to `1.0.2.dev1` with the rule recorded in `docs/INTEGRATION.md`: a pinned commit keeps the same package version, and `pip` treats an installed distribution with that name and version as satisfied, so the server silently keeps the older engine code. The bump makes the new engine install on the next deploy.
- Origin age handling (version `1.0.3.dev1`): a response that already carries an `Age` header from an upstream cache is now stored while its remaining freshness is positive, and the reported `Age` adds the origin age to the time in the cache. This closed the second live blocker on the DMS dev site, where the LiteSpeed layer sends `Age: 81`. Python suite 232 passed, Node suite 48 passed.
